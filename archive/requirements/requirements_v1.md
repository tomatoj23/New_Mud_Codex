# New_Mud 项目需求文档 V1

> 状态：历史需求草案，已废弃。仅用于追溯早期决策，不得作为当前实现、设计或验收依据。当前权威基线为 `requirements_v5.md`。

## 一、项目概述

自研 MUD 引擎（借鉴 Evennia 6.0 设计思想，不使用 Evennia 框架），金庸武侠文字 MUD，多人在线游戏，支持多端访问，采用引擎与内容分离架构。

---

## 二、技术架构

### 2.1 后端：自研引擎

- Web 框架：Django（ORM、Admin 后台、成熟生态）
- 异步/WebSocket：Django Channels（基于 asyncio，WebSocket 原生支持）
- 数据库：Django ORM + SQLite（开发）/ PostgreSQL（生产）
- 借鉴 Evennia 的 Typeclass、命令系统、Scripts 等核心设计思想，自主实现

### 2.2 前端：uni-app（Vue）

- 一套代码编译为 Web（PC/移动浏览器）和微信小程序
- 纯文字为主，保留后期加入图标/图片的扩展性
- 三端体验一致

### 2.3 通信方案

- 主要：WebSocket（实时游戏交互，Django Channels 支持）
- 辅助：REST API（登录、注册、角色管理等）

### 2.4 MUDLib 架构（引擎与内容分离）

- 引擎层：自研引擎提供底层服务（网络、数据库、对象管理、命令路由）
- MUDLib 层：可插拔内容包，定义游戏规则、世界、系统
- 每个 MUDLib 为独立 Python 包，遵循统一接口规范
- 启动时通过配置指定加载哪个 MUDLib，不支持热加载
- 一个服务器实例只加载一个 MUDLib
- 需要 MUDLib 转换器（详见 2.5）

### 2.5 MUDLib 转换器

#### 2.5.1 转换目标

支持将 LPC MUDLib（FluffOS 驱动）转换为本项目自研引擎可加载的格式。已知需兼容的 MUDLib：

| MUDLib | 主题 | 规模 | 位置 |
|:---|:---|:---|:---|
| XKX100 侠客行 | 武侠 | 32门派/130+武功/80+区域 | `D:\My_Projects\xkx100-20201118` |
| ES2 东方故事2 | 武侠 | 小型（~20区域，原型级） | `D:\My_Projects\Mudlibs\ES2-utf8-master` |
| 风云2005 | 武侠 | 大型（~60区域，成熟运营级） | `D:\My_Projects\Mudlibs\fengyun2005-main` |
| 小雨西游 | 西游记 | 大型（~34区域） | `D:\My_Projects\Mudlibs\xymud-main` |
| 神话世界·西游记 | 西游记 | 大型（~27区域） | `D:\My_Projects\Mudlibs\xyj450-master` |
| 炎黄群侠传 | 武侠 | 大型（~80区域，最完整） | `D:\My_Projects\Mudlibs\mud-master` |

#### 2.5.2 共性（转换器基础）

所有 MUDLib 共享的核心模式：
- 语言：LPC，驱动：FluffOS
- 架构：`F_*` Feature mixin + `set()/query()` dbase + Daemon 单例
- 数据组织：`/d/` 下按区域组织房间/NPC/物品
- 全局宏定义：`/include/globals.h`

#### 2.5.3 差异（转换器弹性需求）

| 差异维度 | 具体表现 | 转换器应对 |
|:---|:---|:---|
| 基类路径 | `/std/char` vs `/inherit/char/char` | 路径映射可配置 |
| 技能系统位置 | `/d/skill/` vs `/daemon/skill/` vs `/kungfu/` | 多模式路径解析 |
| NPC 层次 | 单一 `npc.c` vs 5+ 层子类（smart_npc/boss/waiter等） | NPC 模板层次可扩展 |
| Daemon 数量 | 20个 ~ 50个 | 检测引用不存在的 Daemon，跳过或提示 |
| mudlib 根目录 | 根目录 vs `/world/` 子目录 | 支持 mudlib 根偏移配置 |
| 数据持久化 | 纯文件 vs MySQL（mud-master） | 数据库操作代码特殊处理 |
| API 风格 | `set("name", x)` vs `set_name(x)` (mudcore) | 双模式 API 识别与转换 |

#### 2.5.4 LPC → Evennia 核心映射

| LPC 概念 | Evennia 对应 |
|:---|:---|
| `inherit ROOM/NPC/ITEM` | Typeclass 继承 |
| `F_XXX` Feature mixin | Mixin 类或 Handler |
| `set()/query()` (F_DBASE) | `db` 属性系统 |
| Daemon 单例 | Scripts 或 Django 服务 |
| `cmds/std/*.c` 命令 | Command 类 |
| `d/区域/房间.c` 房间 | Room Typeclass 实例 |
| 武功/技能文件 | 武学数据模型 |
| `.o` save file | Django ORM 持久化 |
| `main(object me, string arg)` | `Command.func()` |
| `create()` 初始化 | `at_object_creation()` |

#### 2.5.5 转换策略

- 一次性转换（导入后成为本项目格式，不保持与源 MUDLib 同步）
- 转换器为可配置的工具，通过配置文件适配不同 MUDLib 的路径和风格差异
- 自动转换：结构和数据（房间、出口、NPC、物品、武功定义）
- 半自动适配：游戏逻辑（战斗公式、技能效果脚本），LPC 代码转 Python 需人工审核

### 2.6 账号系统

- 自主注册：手机号注册
- 微信授权登录（微信小程序端）
- 两种方式可绑定同一账号
- 单账号最多创建 10 个角色

### 2.7 多人玩法（MVP）

- PvP：基础对战，竞技场
- 组队：组队探索、组队战斗
- 交易：玩家间物品/货币交易
- 帮派：创建、加入、帮派活动
- 以上均先实现最小可用版本，后续迭代

### 2.8 Web 管理后台

基于 Evennia 自带 Django Admin 扩展，功能包括：

#### 2.8.1 内容制作与管理
- 世界编辑：房间、出口、区域的创建/编辑/删除
- NPC 管理：创建/编辑 NPC，配置属性、对话、行为
- 物品管理：武器、防具、药品、材料等物品的增删改
- 武学管理：门派、武功、招式、内功的配置
- 任务编辑：主线/支线任务的创建和流程编辑
- 事件配置：随机遭遇、世界事件的规则设定

#### 2.8.2 账号与运营
- 账号管理：查询、封禁、解封、密码重置
- 角色管理：查看、修改角色数据
- 在线监控：当前在线玩家、连接状态
- 日志查看：操作日志、异常日志
- 公告系统：游戏内公告发布

## 四、游戏内容设计（来源于原始设计文档，待逐项确认）

### 4.1 角色系统

#### 4.1.1 角色属性：先天-后天双层结构

| 属性类别 | 具体属性 | 作用机制 |
|:---|:---|:---|
| 先天资质（创建时随机，1-30） | 根骨、悟性、福缘、容貌 | 影响后天属性成长率 |
| 后天属性（修炼提升） | 力量、敏捷、体质、精神 | 直接影响战斗数值 |
| 动态状态 | 气血、内力、精力 | 当前/最大值，战斗中实时变化 |
| 江湖身份 | 门派、善恶值、声望 | 影响NPC态度、剧情分支、可学武学 |

#### 4.1.2 角色成长：经验-等级-境界三层递进

| 阶段 | 名称 | 特征 | 解锁内容 |
|:---|:---|:---|:---|
| 1-30级 | 习武之人 | 学习基础招式，门派选择窗口期 | 入门武学、基础任务 |
| 31-60级 | 江湖好手 | 内功入门，可执行中级任务 | 进阶武学、门派职位 |
| 61-90级 | 武林高手 | 自创招式，开宗立派资格 | 绝世武学、隐藏剧情 |
| 91-100级 | 一代宗师 | 影响世界结局 | 最终挑战、多结局分支 |
| 突破 | 返璞归真 | 多周目继承 | 隐藏内容、新轮回 |

### 4.2 内力系统

| 子系统 | 核心机制 | 策略深度 |
|:---|:---|:---|
| 丹田容量 | 决定内力上限，随内功层级提升 | 资源管理核心 |
| 经脉系统 | 十二正经+奇经八脉，影响运转效率 | 冲穴顺序规划 |
| 内力属性 | 阴阳刚柔，与招式匹配/相克 | 战斗策略选择 |
| 走火入魔 | 透支、冲突、干扰时概率触发 | 风险收益权衡 |

### 4.3 武学系统

#### 4.3.1 武学数据模型

| 层级 | 数据实体 | 核心字段 |
|:---|:---|:---|
| 武功（Kungfu） | 招式集合 | 名称、门派、类型、品质、学习条件 |
| 招式（Move） | 具体技能 | 消耗、冷却、伤害公式、效果脚本、克制关系 |
| 内功（Neigong） | 心法修为 | 层数、运转效果、冲突关系、走火入魔风险 |
| 轻功（Qinggong） | 移动身法 | 速度加成、闪避加成、特殊地形通过 |
| 天赋（Talent） | 被动成长 | 节点网络、解锁条件、效果组合 |

#### 4.3.2 武学领悟链条

| 阶段 | 达成条件 | 核心收益 |
|:---|:---|:---|
| 学习 | 获得秘籍或拜师 | 解锁招式基础形态 |
| 熟练 | 反复使用积累熟练度 | 伤害系数提升、消耗降低 |
| 精通 | 熟练度满，选择专精方向 | 单式强化或全套均衡 |
| 变招 | 精通后概率领悟 | 情境特殊效果 |
| 自创 | 多门武学精通后融合 | 命名新武学，写入独门秘籍 |
| 传承 | 通关后选择 | 带入新周目，或成为NPC师父 |

### 4.4 战斗系统

#### 4.4.1 战斗模式

| 模式 | 机制 | 适用玩家 |
|:---|:---|:---|
| 回合制 | 玩家思考时间无限制 | 经典MUD爱好者 |
| 限时回合制 | 每回合30秒 | 中等操作需求 |
| 即时制 | 时间条机制，行动速度决定频率 | 动作向玩家 |

#### 4.4.2 招式相克

| 招式类型 | 克制 | 被克 | 代表武学 |
|:---|:---|:---|:---|
| 拳 | 掌 | 指 | 罗汉拳、七伤拳 |
| 掌 | 指 | 拳 | 降龙十八掌、黯然销魂掌 |
| 指 | 拳 | 掌 | 一阳指、弹指神通 |
| 剑 | 刀 | 棍 | 独孤九剑、太极剑 |
| 刀 | 棍 | 剑 | 火焰刀、胡家刀法 |
| 棍 | 剑 | 刀 | 打狗棒法、伏魔杖法 |

#### 4.4.3 环境互动

| 环境因素 | 影响 |
|:---|:---|
| 地形 | 高处+命中，水域限制部分武学，密林+闪避 |
| 天气 | 雨天-火系+水系，雪天+冰系，大风-暗器精度 |
| 光照 | 夜间-命中，火把/夜视武学可抵消 |

### 4.5 物品系统

| 物品类型 | 装备槽位 | 特殊机制 |
|:---|:---|:---|
| 武器 | 主手/副手 | 招式加成、耐久损耗、淬毒 |
| 防具 | 头/身/腰/腿/足 | 伤害减免、套装效果 |
| 饰品 | 项链/戒指×2/玉佩 | 属性加成、特殊被动 |
| 药品 | 快捷栏 | 冷却时间、耐药性 |
| 材料 | 背包 | 叠加99/999，用于锻造/炼丹 |
| 秘籍 | 背包 | 阅读领悟、销毁后消失 |
| 任务物品 | 任务栏 | 不可丢弃、自动追踪 |

耐久度系统：战斗损耗耐久，修理消耗金钱与材料。绑定规则：拾取绑定、装备绑定、任务绑定。

### 4.6 地图系统

#### 4.6.1 三维坐标

| Z值 | 层级 | 典型场景 | 移动方式 |
|:---|:---|:---|:---|
| Z>0 | 高空 | 鹰巢、飞剑对决 | 绝顶轻功/特殊道具 |
| Z=1 | 屋顶/树冠 | 夜行探查、伏击 | 上乘轻功 |
| Z=0 | 地面 | 街道、广场、平原 | 正常行走 |
| Z=-1 | 地下室/墓穴 | 密室、藏宝洞 | 楼梯/暗门 |
| Z<-2 | 深层地下 | 地牢、矿脉、秘境 | 特殊通道 |

#### 4.6.2 区域动态加载

| 区域类型 | 范围 | 加载策略 |
|:---|:---|:---|
| 活跃区 | 玩家周围3×3×2 | 完整对象实例 |
| 预加载区 | 距离2-3 | 基础数据，异步加载 |
| 休眠区 | 距离>3 | 序列化后内存释放 |

#### 4.6.3 寻路

- A*算法，房间为节点，出口为边
- 权重考虑距离、危险度、通行条件
- 三维曼哈顿距离启发函数

## 六、安全性、稳定性、扩展性（已确认）

### 6.1 安全性

- 通信安全：WebSocket/REST API 全部走 HTTPS/WSS
- 认证安全：JWT Token 机制，Token 过期刷新，异地登录检测
- 数据安全：密码 bcrypt 加盐哈希，手机号等敏感信息加密存储
- 防作弊：所有游戏逻辑服务端计算，客户端只做展示；关键操作服务端校验
- 防攻击：接口限流（Rate Limiting），防 SQL 注入（Django ORM），XSS 过滤
- 权限控制：管理后台分角色权限（超管/运营/内容编辑），操作审计日志
- 微信小程序：遵循微信安全规范，敏感数据解密走服务端

### 6.2 稳定性

- 进程守护：Supervisor 或 systemd 管理 Evennia 进程，崩溃自动重启
- 数据库备份：定时自动备份，支持快速恢复
- 异常处理：全局异常捕获，关键错误不影响其他玩家
- 压力测试：上线前做并发压测，确定单实例承载上限
- 日志系统：分级日志（DEBUG/INFO/WARNING/ERROR），便于排查问题
- 优雅停机：维护时通知在线玩家，保存所有状态后再关闭

### 6.3 扩展性

- MUDLib 可插拔：不同内容包可替换加载
- 模块化：各系统（战斗、武学、任务、交易）松耦合，可独立迭代
- API 版本化：REST API 带版本号（v1/v2），前端升级不影响旧版
- 内容热更新：不停服更新游戏内容（房间、NPC、物品），代码更新需重启
- 单实例垂直扩展，不做多实例水平扩展
- 不支持第三方插件/MOD
