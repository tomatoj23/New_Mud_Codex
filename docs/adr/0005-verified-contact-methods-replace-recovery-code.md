# 已验证联系方式取代 RecoveryCode

Status: accepted

新注册必须先证明一个恢复渠道可用；首期渠道是邮箱，未来可以独立增加短信。登录仍只使用账号名和密码。`VerifiedContactMethod` 是 User 已证明控制的邮箱或手机号；每个 User 每种渠道最多一个 active 或 unreachable 联系方式，同一规范化联系方式最多属于一个未永久退休 User。`VerificationChallenge` 按注册、密码重置、账号重新启用、绑定或换绑等用途，以及渠道、目标联系方式和适用 User 隔离，短期有效且只能消费一次。它不能跨用途使用，也不是登录凭据、长期所有权证明或 Character 控制证明。

Public V1 的全部可交互人员账号（包括管理员）都必须持有 VerifiedContactMethod；隔离测试可以使用不可进入生产配置的显式 bypass。机器身份不伪装成人类 User。

RecoveryCode 不再签发或接受，历史记录只保留为已撤销的审计事实。当前既有账号和 code 都是非生产开发测试数据，因此不建立旧账号兼容恢复承诺；切换不得被解释为可以自动删除数据。密码重置只改变 User 凭据，不改变 GameAccount 生命周期；`cooling_off` 账号通过用途独立的账号重新启用 challenge 恢复为 `active`，永久 `retired` 的账号不能恢复。任何成功的密码重置、账号重新启用或恢复渠道换绑都撤销既有认证状态，并且不自动登录、恢复 Presence 或取得 Character 控制权。

邮箱和未来手机号是恢复渠道，不是登录名或免密码登录方式。未来短信上线后，新注册可以在验证邮箱或验证手机号之间选择；同时拥有两种渠道时，任一渠道可以发起恢复并向另一渠道发送安全通知。换绑必须重新验证当前密码和新联系方式；仍有另一可用渠道时也验证该渠道，丢失唯一渠道时进入安全等待期。密码和全部已验证渠道都丢失时，没有自助或人工重分配所有权的路径，支持人员只能冻结账号并保全审计。

`cooling_off` 期间保留联系方式以支持重新启用；进入 `retired` 后撤销并解绑联系方式、释放唯一性，审计不保留完整地址。投递失败不会自动解绑或转移所有权；持续不可达的联系方式停止用于恢复，并在用户成功登录后提示更换。163 SMTP 只用于本机开发和人工 smoke；Public V1 开放注册前必须使用受控域名和正式邮件服务，并具备反伪造、退信、限额、告警和基本送达证据。

本 ADR 取代 ADR-0004 中以 RecoveryCode 作为密码找回、账号重新启用和轮换证明的决定。ADR-0004 关于恢复身份后撤销旧会话与控角状态、不自动恢复 Presence，以及 `PresenceRecovery` 与显式 takeover 必须分离的边界继续成立；Character、Presence、PresenceRecovery 和 takeover 的实现不进入本次认证基线修订。

考虑过通过邮箱发送长期 RecoveryCode、让两套恢复根长期并存，以及允许人工依据游戏资料重分配账号。前两者保留了长期秘密的泄漏面并扩大恢复歧义，后者缺少可靠的所有权证明，因此不采用。
